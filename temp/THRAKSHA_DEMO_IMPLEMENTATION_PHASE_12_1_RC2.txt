
# THRAKSHA — PHASE 12.1 IMPLEMENTATION GUIDE

## PRIVATE ALPHA RC2 — REAL APP VISIBILITY + PERMANENT SIGNING + FINAL WORDING FIX

## 1. PURPOSE

Phase 12.1 converts the Phase 12 RC1 into the first Thraksha APK intended for genuine everyday-phone private-alpha use.

Only three issues are in scope:

1. **Release scanner visibility**

   * release APK must be able to discover and scan relevant third-party installed apps.

2. **Permanent private-alpha signing identity**

   * replace temporary Android debug signing with a dedicated Thraksha signing key.

3. **Consumer wording correction**

   * remove the Samsung-facing “eyes and ears active 24/7” overclaim and verify other nearby wording remains accurate.

Then build and verify:

`thraksha-guardian-1.0-privatealpha-rc2.apk`

Do not add features.

# TASK B — PRIVATE-ALPHA SIGNING

## 10. PURPOSE

RC1 currently uses:

`CN=Android Debug`

RC2 needs a dedicated Thraksha signing identity.

This signing key will become the identity used for future private-alpha updates.

---

# 11. IMPORTANT USER CHECKPOINT

Claude Code must **STOP before generating the signing key** and tell the user:

> `SIGNING KEY CREATION REQUIRED`

At that point I will create/approve the permanent Thraksha private-alpha keystore.

Do not silently generate passwords.

Do not put signing secrets into source code.

Do not commit a keystore.

---

# 12. WHEN THE USER CREATES THE KEY

The user creates the key **after Claude finishes Task A and prepares the signing configuration**, but **before RC2 is built**.

That is the correct timing.

---

# 13. WHERE TO STORE THE KEY

The real signing keystore must be stored **outside the Git repository**.

Example concept:

`C:\Users\<user>\secure\thraksha\thraksha-private-alpha.jks`

or another private secure directory.

Do NOT store it under:

* project root
* `app/`
* `temp/`
* `model/`
* `tools/`
* `.claude/`
* Git-tracked locations.

Also create at least one secure backup outside the development laptop before treating it as permanent.

Do not put the backup inside the repository.

---

# 14. PASSWORD HANDLING

Signing passwords must NOT appear in:

* `build.gradle.kts`
* source files
* manifest
* `gradle.properties` committed to Git
* temp docs
* Claude prompts
* screenshots
* logs intended for sharing.

Prefer:

* environment variables;
* untracked local properties;
* secure credential mechanism.

Claude may prepare placeholders/configuration but must never invent and commit credentials.

---

# 15. SIGNING CONFIGURATION

Implement a safe release signing configuration.

Conceptually consume:

* keystore path
* store password
* key alias
* key password

from local/untracked sources.

If credentials are absent:

release build should fail clearly rather than fall back silently to debug signing.

No silent debug-key fallback.

---

# 16. SIGNER VERIFICATION

After RC2 build verify independently:

* signer certificate subject
* SHA-256 certificate fingerprint
* APK signature schemes
* `debuggable=false`
* application ID
* versionName/versionCode.

Record in:

`temp/phase12_1/PHASE12_1_SIGNING.md`

The signer must NOT report:

`CN=Android Debug`.

---

# 17. KEY CONTINUITY WARNING

Document prominently:

> Future Thraksha private-alpha APK updates must use this same signing key.

Loss of the signing key means future builds cannot update the installed app under the same package identity.

Do not rotate casually.
